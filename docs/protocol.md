# 4117 机芯 UVC 通信说明

> 本文所有内容来自 **USB 总线抓包观察**（usbmon + Android USB Host 行为差异对比），
> 目的是让第三方软件能与硬件互操作。**不包含任何厂商 SDK 代码、反编译产物或固件内容。**

## 1. 设备

| 项 | 值 |
|---|---|
| VID:PID | `2bdf:0101`（"HIK HikCamera"） |
| 设备类 | UVC 1.10（`uvcvideo` 驱动可识别，但厂商功能需走 XU） |
| 扩展单元 | `bUnitID = 10`，`bmControls = 0x3FF`（选择子 1..10） |
| XU GUID | `{a29e7641-de04-47e3-8b2b-f4341aff003b}` |
| 视频 | MJPEG，常见 320×240 / 640×360，bulk IN EP `0x81` |

## 2. 控制传输帧格式

所有厂商命令都通过 `wIndex = 0x0A00` 的 XU 请求。

### 2.1 选择命令（select）

```
21 81  wValue=组号<<8  wIndex=0x0A00  len=4   data = { 组号, 0x00, 子功能, 0x01 }
```

### 2.2 写数据（SET_CUR）

```
21 01  wValue=组号<<8  wIndex=0x0A00  len=3+N  data = { 0x03, 0x88, 0x01 } + N 字节结构体
```

`0x03` 是"头长度"，`0x88` 是标志，`0x01` 是通道。

### 2.3 读数据（GET_CUR）

```
A1 81  wValue=组号<<8  wIndex=0x0A00  len=可读长度
```

**坑**：`GET_LEN`（`0x85`）会清掉待读事务，且之后 `GET_CUR` 全为 0。
正确顺序是 **select → 直接 GET_CUR**，中间不能插 `GET_LEN`。

### 2.4 读响应格式

```
{ 组号, 0x00, 子功能, 状态 } + 数据
```

第 4 字节为 `1` 表示有数据，`0` 表示设备无数据（命令被拒绝或未就绪）。

## 3. 已验证的命令

| 命令 | 组/子 | 方向 | 结构体 | 说明 |
|---|---|---|---|---|
| 设备信息 | 1 / 1 | 读 | ASCII | 如 `5.5.10 build 210208` |
| 测温基本参数 | 3 / 1 | 读/写 | 47 B | 见 3.1 |
| 测温模式 | 3 / 2 | 读/写 | 小结构体 | |
| 亮度 | 2 / 1 | 读/写 | 5 B | 见 3.2，**不需要 select** |
| 对比度 | 2 / 2 | 读/写 | 5 B | 见 3.2，**不需要 select** |

### 3.1 测温基本参数（47 字节，写模板）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 通道（固定 1） |
| 1 | u8 | 测温使能 |
| 2 | u8 | 显示最高温 |
| 3 | u8 | 显示最低温 |
| 4 | u8 | 显示平均温 |
| 5 | u8 | 单位（0=℃） |
| 6 | u8 | 量程 |
| 12..15 | u32 | 光学参数（1200） |
| 16..19 | u32 | 发射率 ×100（98 = 0.98） |
| 20 | u8 | 距离单位 |
| 21..24 | u32 | 距离（100） |
| 26..29 | u32 | 反射温度 ×10 |

> **注意**：读回来的结构体与写入布局**相差 1 个字节**（发射率在读取数据中位于偏移 15，写入模板中是 16）。
> 直接"读-改-写"会把数据写乱，因此本项目使用固定模板写入，只改 2/3 两个显示位。

### 3.2 亮度 / 对比度（5 字节，无需 select）

```
21 01  wValue=0x0200  wIndex=0x0A00  len=5   data = { 0x03, 0x88, 参数, 0x01, 值 }
参数：0x01 = 亮度，0x02 = 对比度；值范围 1..100
```

示例（抓包）：

```
亮度 60   : 21 01 0200 0a00 0005 = 03 88 01 01 3C
对比度 70 : 21 01 0200 0a00 0005 = 03 88 02 01 46
```

若像测温命令那样先发 select 再写，设备会接受传输但**不执行**——这是最容易踩的坑。

## 4. 视频流

每个 bulk 包开头都有一个 UVC payload header（本设备固定 2 字节 `02 80`），
必须按 `buf[0]` 给出的长度剥掉，否则拼出来的 JPEG 会花屏。

## 5. 未解决的命令

`2046`（抓图 + 温度矩阵）与 `2047`（ROI 最高温搜索）在本固件上：

- 请求被接受（回显 `03 00 09 00` / `03 00 0a 00`），但状态位恒为 `0`；
- 按"先读 4 字节头（长度在 offset 1）、再读正文"的两段式读取，头为全 0；
- 大长度 `GET_CUR` 会阻塞不返回。

疑似请求结构体或前置条件与固件版本不匹配。**本项目不依赖这两条命令。**

## 6. 安全提醒

- 连续对同一命令写入可能让机芯进入"接受但不执行"的状态，**需要断电重启**才能恢复；
- 本项目所有写入都是单次、带限幅的，且不使用"读-改-写"；
- 如果你在实验新命令，建议每次只发一条，并准备好断电重插。
